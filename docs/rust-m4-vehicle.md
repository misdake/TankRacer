# M4 vehicle rendering

## M4.1 accepted (2026-11-17)

The Rust browser now draws the authored body, turret and gun instead of the box.
This increment changes render extraction and submission only. Game/physics source,
fixed updates, input rules, RNG, spawn and camera behavior are unchanged.

### Resource and state ownership

- `scene::vehicle::VehicleScene` reads the existing `VehicleModel` and `pose::State`.
  Each part has local geometry, a material atlas, a world transform and a geometry
  revision. It never receives mutable gameplay state.
- Local model vertices are in world units (/128); published part translations
  are in physics units (/1024). The boundary reflects Z once. Part poses already
  contain authored offsets, body lean, turret yaw and gun pitch/recoil; the renderer
  does not reapply those operations or compose them under a second body transform.
- Current private geometry is authoritative, including body/turret collision
  damage, hidden faces and gun-vertex recoil. A small exact geometry comparison
  detects changes without modifying simulation owners or introducing hash collisions.
  Only changed parts are prepared/uploaded. Pose-only updates use model uniforms.
- One vehicle atlas reuses the existing clamped, padded, premultiplied texture
  policy. Opaque, masked, double-sided and blended faces use the existing explicit
  material states. Blended parts join the same triangle order as world/scenery;
  opaque vehicle parts write depth before all blended geometry.
- `web::vehicle_view` owns GPU resources. Atlas pixels are released after upload;
  CPU geometry/cache metadata and GPU resources have normal session ownership.
  Vehicle render caches are reported separately from extra per-map preprocessing.

### Verification

Focused verification passed; unrelated C module suites were not repeated:

- All eight scene tests: six existing tests and two new asset-backed vehicle tests.
  The new tests prepare all 15 cars at four articulated poses (4,024 rendered
  triangles across the cases), compare every render vertex against an independent
  source row-vector calculation, and check that poses/model geometry are unchanged.
  Recoil and hidden/damaged geometry invalidate only the affected part.
- Native scene and Wasm adapter Clippy checks pass with warnings denied.
- Actual browser: 144 GPU pixel cases, eight depth comparisons, 81 blend
  transitions; existing 120-update direct-drive and 24-update keyboard/handbrake
  native/Wasm final physics/RNG comparisons; ten shared-scenery probes and reloads.
  Repeated rendering and three camera-only inspections preserve the physics/RNG
  checkpoint, with zero idle vertex/index/instance uploads.
- Inspected front, side and rear-quarter screenshots generated by the browser
  test. Meshes, texture binding, facing and part attachment are visible. These
  are free-camera inspections, not qualification of original game camera modes.
- Production build passes; test probes are absent from its exports. C source
  preservation passes (97 modules, 244 unchanged source files, two audio packs).
  The earlier M3 C qualification remains the physics baseline; this increment
  does not claim a new complete Player/race comparison.

### Measured result and remaining scope

Default vehicle: **3 parts, 61 triangles, 3 opaque draws**, one atlas and
**16,113 B** of vehicle render caches (GPU storage excluded). Default scene:
**398 draws / 10,082 triangles / 22 pipeline changes**, versus 396 / 10,033 with
the box. Production Wasm: **716,818 B**.

Extra resident map data: ENGLAND **767,421 B** (781,925 B shattering peak), SWAMP
**879,610 B**, BIO **949,436 B**. The 16-byte increase is world-view statistics
bookkeeping; vehicle-specific caches are separate. All tested totals stay below
1,000,000 B. Other maps' full live aggregates remain unqualified.

M4.2 adds tracks/wheels and their animation. M4.3 adds original cameras, shadows
and extra vehicle layers/attachments. M4.1 displays authoritative turret/gun poses;
the enclosing original turret-key/fire gameplay path remains later integration.
The current runtime still starts immediately and is not a complete race.
